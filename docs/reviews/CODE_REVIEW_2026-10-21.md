# Stock Tracker：面向日常使用的代码评审

- 日期：2026-10-21。
- 代码基线：`main` / `217d12466139798d3409966982f89a398d76dadb`。
- 目标：个人投资者每日查看观察池、理解策略条件变化、收到可信日报；作为后续实施方案的依据。
- 配套方案：[日常使用优化实施计划](../planning/DAILY_USE_OPTIMIZATION_PLAN.md)。本次提交只包含文档。

实施范围修订（2026-10-21）：用户决定不提供人工行情补录或修改。以下建议同步限定为 yfinance 采集、来源修订与缺失状态处理，原代码基线和离线复现结论不变。

## 1. 结论

在现有 Stock Tracker 上改造，比把 Market Lab 的研究平台界面继续改造成股票看板更直接。已有 FastAPI、Jinja2、Chart.js、SQLite、行情采集、四类个股策略、市场背景和 Telegram 日报，足以作为增量改造的基础。

最需要解决的是数据与计算结果是否属于同一交易日，以及页面看到的结果是否真实反映当前条件。换皮肤不能解决这些问题。当前存在旧信号被展示为最新、缺基准仍判定 Stage2、长期进程继续读旧缓存、VCP 状态未退出等风险。

系统已经使用数据库，并非纯 CSV 项目：`lib/db.py` 定义了行情、策略、观察池、运行和通知等表，路径为 `data/stock_tracker.db`，启用 SQLite WAL。CSV、JSON 和数据库仍同时承担部分数据来源职责，造成不同入口行为不一致。建议统一数据库主存储，保留 CSV 导出与旧版迁移校验，暂不引入 PostgreSQL。

## 2. 评审方法与边界

读取了该提交递归树，下载并按 Git blob SHA 校验了 63 个源代码、配置和文档文本文件；检查了 Web 路由与模板、数据库、采集与策略脚本、通知以及部署入口。对 Python 源文件做了语法解析，并对五处关键行为进行了离线函数级复现。

离线复现从当前源码 AST 提取实际函数，注入合成行情或数据库替身，不访问行情服务、生产数据库和 Telegram。它能证明指定函数行为，不能代替完整应用、真实数据和 VPS 验收。当前环境没有 FastAPI，未启动整站；未验证线上部署版本、定时任务、生产数据库或 notification-hub 当前 API。仓库树中未发现自动化测试目录或 CI 工作流。历史日报产物不作为策略正确性的证据。

## 4. 已完成的离线复现

| 问题 | 输入 / 操作 | 实际结果 |
|---|---|---|
| 节假日 | 对 `is_trading_day` 传入 2026-12-25 | 返回 `true`；该实现没有假日分支 |
| 缺基准 | 300 条递增合成收盘价，SPY 缺失 | C8 为 `null`，`is_stage2=true`，通过数 / 总数为 7/7 |
| 旧缓存 | 首次读取后把替身数据库最新值从 2 改为 3，再读同 ticker | 返回值仍为 2，并且是同一缓存对象 |
| VCP 未清退 | 对实际状态保存函数传入空候选集合 | 数据库写入次数为 0，旧状态没有被清退 |
| 历史冒充最新 | 市场日期为 2026-10-20，当日零信号，历史存在 2026-10-19 信号 | 页面上下文日期为 2026-10-20，展示信号日期为 2026-10-19 |

后续实现应把这些复现转换为仓库内回归测试，并增加真实函数调用链的集成测试。此文不把离线替身测试描述成部署验收。

## 5. 交易语义评审

### Stage2

保留趋势模板作为观察池筛选工具。必须先解决历史长度、均线斜率窗口和基准日期对齐：当前 52 周计算可能使用不足 252 个交易日的窗口；SMA200 前值的窗口边界需要明确；与 SPY 的收益比较不能只按数组位置截取而不对齐日期。SPY 作为基准本身应与被筛选股票区分。

“趋势强度”中价格远离均线不应直接解释成更适合买入；应同时展示距离均线、近期高点、数据日期和条件明细。通过模板只表示满足定义，不代表胜率、确定买点或建议仓位。

### VCP

当前实现是接近高点、布林带宽、成交量、趋势和均线位置等六项条件的组合，满足至少四项即可入选；因此收缩或量缩不成立时也可能入选。它没有完整识别连续多轮收缩和放量突破。

第一轮应诚实命名为“收缩候选”，修复依赖和退出状态。若要求收缩、量缩成为硬门槛，应作为独立规则版本并用样本对照评审，不能作为普通 bug 修复偷偷改变历史含义。完整结构识别和突破确认是后续策略迭代。

### Bottom Fisher、Buying Checklist、Market Pulse

Bottom Fisher 是逆势观察，应该与 Stage2 顺势候选分区。Checklist 的通过比例不是概率，缺失项不能被省略后提高通过率。周线条件应说明使用完整周还是本周暂态，避免盘前“周确认”的错觉。

Market Pulse 当前主要使用股指 ETF、VIX 和观察池宽度，不能包装成包含美债、实际利率和 BEI 的宏观系统。显示观察池样本数和口径，避免把自选股比例解释为全市场宽度。

## 6. 用户应该得到什么

每天打开网站，应能直接回答：价格到哪一天；哪些数据没更新；我的哪些股票满足趋势条件；哪些在收缩观察；哪些已退出；有哪些逆势候选；为什么产生变化。纽约时间 06:00 的日报应与同一发布批次的页面一致，缺失也明确报告。

建议保留现有策略计算能力和 Web 技术栈，借鉴 Market Lab 的暖白背景、深蓝文字、克制状态色和表格层级。版本与审计数据留在后台支持追溯，用户默认看到日期、条件和原因。宏观数据增量后续单独做，不阻塞股票日常闭环。
